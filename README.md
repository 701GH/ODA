# RAGNet-3DOI Audit

Item-by-item manual audit and revision of the 3DOI subset of [RAGNet](https://arxiv.org/abs/2507.23734).

All 1,013 image–instruction pairs were read one by one and given a final verdict of **keep**, **edit** or **reject**. The released revised benchmark contains **997** items; the full audit record is public as well.

## Why this audit

RAGNet-3DOI instructions were generated by GPT-4 and released without manual validation. We found that a large share of them do not match their ground-truth mask: the task the model is asked to complete is not the task it is scored on. On such samples a score difference reflects a defect of the data rather than a difference in method capability.

## Problems found

Three categories dominate.

- **Granularity mismatch** — the instruction asks about the whole object while the mask labels only one part of it. The mismatch shows up as a change of verb: the original uses a *finding* verb (`find`, `locate`, `show`), which only asks where the object is, while the revision uses a *handing* verb (`hand`, `pass`, `bring`), which asks for the part that can be grasped and handed over. 68 edits were classified here during the audit.
- **Object mismatch** — the instruction describes one object while the mask corresponds to a different one. A few items go further and invert the action itself.
- **Defective mask** — the instruction is fine and the mask is what fails, because it cannot express the structure of the part at the target resolution. Items in this category are rejected without exception.

We did not correct these masks, because pixel-wise correction has no executable acceptance criterion in this task: how far a part boundary extends, and whether a small hole is kept or filled, both change the denominator of the intersection-over-union directly, and whether a mask we redraw is more accurate than the original cannot be judged objectively. A redraw that no independent check validates would introduce a new and hard-to-notice class of error.

Some examples:

| id | verdict | original instruction | revised instruction | note |
| --- | --- | --- | --- | --- |
| 104 | edit | "Find a knife, please." | "Hand me a knife, please." | mask covers only the handle |
| 417 | edit | "Show me where the wok is located." | "Could you bring me a wok?" | mask covers only the handle |
| 816 | edit | "Can you fill this jug with water?" | "Pass me the kettle." | mask is a kettle |
| 619 | edit | "Can you bring me a vase, please?" | "Can you bring me a flower pot, please?" | mask is a flower pot |
| 568 | edit | "Can you open the door for me?" | "Can you close the door for me?" | mask is a closed door |
| 712 | reject | "Please find the scissors." | unchanged | the hole is filled in, the two handles merge |
| 380 | reject | "Let's hang a picture frame on the wall." | unchanged | mask covers the picture, not the frame |

## How the audit was done

All 1,013 items were read in **two full passes by a single annotator**: the first pass gave a verdict for every item, the second pass re-read all of them, and items whose two verdicts disagreed were adjudicated once more. Reading relied only on the image, the instruction and the ground-truth mask — **no model prediction was consulted** — so the verdicts are independent of the method being evaluated. Because both passes came from the same person, no inter-annotator agreement coefficient is reported, and the released record does not distinguish the two passes.

An instruction matches its mask when, following that instruction, the region that needs to be touched is exactly the region the mask labels. If not, the instruction is edited; if the mask itself cannot express the structure of that part, the sample is rejected.

## The same problem elsewhere

The three categories also occur outside RAGNet-3DOI. A sampling check on the easy and hard splits of RAGNet-HANDAL and on ReasonAff showed the same disagreement between instruction and ground-truth mask. That check recorded no systematic sample size or sampling method, so it is reported only as a clue that the phenomenon is not isolated; we do not claim generality on its basis. Those sets also contain a further difficulty this audit did not address: some of their instructions are themselves ambiguous, in that no single correct region is determined.

RAGNet-3DOI was chosen for the full audit on grounds of scale. With 1,013 image–instruction pairs an item-by-item reading is feasible; the other subsets are larger, and reading them in full would exceed the effort available here.

### `tasks.jsonl`

One JSON object per line, four fields:

| Field | Meaning |
| --- | --- |
| `id` | sample id |
| `image` | relative path to the image |
| `mask` | relative path to the ground-truth mask |
| `question` | the instruction of this version |

```json
{"id": 0, "image": "images/0000.jpg", "mask": "masks/0000.jpg", "question": "Please bring a bowl to the dining table."}
```

### `review_log.jsonl`

Covers all 1,013 items, so it has 16 more entries than `tasks.jsonl`.

| Field | Meaning |
| --- | --- |
| `id`, `image`, `mask` | as above |
| `question` | the instruction of this version |
| `original_question` | the instruction before revision |
| `review_status` | `keep`, `edit` or `reject` |
| `source_image`, `source_mask` | where the sample comes from in 3DOI |

The two versions of a sample can be compared directly:

```json
{"id": 2, "image": "images/0002.jpg", "mask": "masks/0002.jpg", "question": "Could you please hand me a bowl?", "original_question": "Could you please hand me a bowl for the salad?", "review_status": "edit", "source_image": "data/3doi/images/AR_j1yJlIVn3vY_2_1440_65.jpg", "source_mask": "data/3doi/masks/bowl/AR_j1yJlIVn3vY_2_1440_65.jpg"}
```

`source_image` and `source_mask` are 3DOI-internal relative paths kept for traceability; they do not refer to any local directory.

## Usage

```python
import json

with open("tasks.jsonl", encoding="utf-8") as f:
    tasks = {r["id"]: r for r in map(json.loads, f)}

with open("review_log.jsonl", encoding="utf-8") as f:
    log = [json.loads(line) for line in f]

rewritten = [r for r in log if r["review_status"] == "edit"]
print(len(tasks), "published;", len(rewritten), "instructions rewritten")
```

To evaluate on the revised version, use `question` and `mask` from `tasks.jsonl`. To compare a model before and after revision, align the two versions of a sample with `review_log.jsonl`.

## Relation to the original set

Of the 1,013 original image–instruction pairs, **616** are kept (60.8%), **381** are edited (37.6%) and **16** are rejected (1.6%), leaving 997. **221 of the 381 edits (58%) remove a content word from the original instruction** — they change the target the instruction refers to rather than only rephrasing it. A proportion that high indicates the mismatch is systematic rather than a scattering of typos. Both versions share the same images and masks and differ only in the instruction text.

One of the 16 rejects is **id 509**, whose image file `images/0509.jpg` is 0 bytes and unreadable in the original release. It still went through the audit, because its instruction and its mask are readable and the verdict rests on those; it is rejected and skipped during evaluation, which is why the original version evaluates 1,012 of its 1,013 samples.

Masks are single-channel grayscale, with pixel values concentrated at 0 and 255. Any binarization threshold from 10 to 245 gives the same foreground; we use 128.
