# RAGNet-3DOI Audit

Item-by-item manual audit and revision of the 3DOI subset of [RAGNet](https://arxiv.org/abs/2507.23734).

All 1,013 image–instruction pairs were read one by one and given a final verdict of **keep**, **edit** or **reject**. The released revised benchmark contains **997** items; the full audit record is public as well.

## Why this audit

RAGNet-3DOI instructions were generated by GPT-4 and released without manual validation. We found that a large share of them do not match their ground-truth mask: the task the model is asked to complete is not the task it is scored on. On such samples a score difference reflects a defect of the data rather than a difference in method capability.

## Problems found

Three categories dominate.

- **Granularity mismatch** — the instruction asks about the whole object while the mask labels only one part of it, e.g. id 104 "Find a knife, please.", whose mask covers only the handle.
- **Object mismatch** — the instruction describes one object while the mask corresponds to another, e.g. id 619, where the instruction asks for a vase but the mask is a flower pot.
- **Defective mask** — the mask cannot express the structure of the part, e.g. id 712, where the hole of a pair of scissors is too small to survive and the two handles merge into one solid region. All such items are rejected.

We did not correct these masks: whether a mask we redraw is more accurate than the original cannot be judged objectively. `AUDIT.md` gives the full protocol, the examples by sample id, and the per-item statistics.

The same phenomenon also appears in a sampling check of RAGNet-HANDAL and ReasonAff; that check was not a systematic sampling, so we do not claim generality on its basis. Owing to the amount of work involved, we did not conduct a full check and revision of those evaluation sets, and the revision released here covers RAGNet-3DOI only.

### `tasks.jsonl`

One JSON object per line, four fields:

| Field | Meaning |
| --- | --- |
| `id` | sample id |
| `image` | relative path to the image |
| `mask` | relative path to the ground-truth mask |
| `question` | the instruction of this version |

```json
{"id": 0, "image": "images/0000.jpg", "mask": "masks/0000.jpg", "question": "Please bring a bowl to the dining table."}
```

### `review_log.jsonl`

Covers all 1,013 items, so it has 16 more entries than `tasks.jsonl`.

| Field | Meaning |
| --- | --- |
| `id`, `image`, `mask` | as above |
| `question` | the instruction of this version |
| `original_question` | the instruction before revision |
| `review_status` | `keep`, `edit` or `reject` |
| `source_image`, `source_mask` | where the sample comes from in 3DOI |

The two versions of a sample can be compared directly:

```json
{"id": 2, "image": "images/0002.jpg", "mask": "masks/0002.jpg", "question": "Could you please hand me a bowl?", "original_question": "Could you please hand me a bowl for the salad?", "review_status": "edit", "source_image": "data/3doi/images/AR_j1yJlIVn3vY_2_1440_65.jpg", "source_mask": "data/3doi/masks/bowl/AR_j1yJlIVn3vY_2_1440_65.jpg"}
```

`source_image` and `source_mask` are 3DOI-internal relative paths kept for traceability; they do not refer to any local directory.

## Matching criterion

An instruction matches its mask when the region that needs to be touched under that instruction is exactly the region marked by the mask. All 1,013 items were read in two full passes by a single annotator, relying only on the image, the instruction and the mask, and `review_status` holds the final verdict.

## Usage

```python
import json

with open("tasks.jsonl", encoding="utf-8") as f:
    tasks = {r["id"]: r for r in map(json.loads, f)}

with open("review_log.jsonl", encoding="utf-8") as f:
    log = [json.loads(line) for line in f]

rewritten = [r for r in log if r["review_status"] == "edit"]
print(len(tasks), "published;", len(rewritten), "instructions rewritten")
```

To evaluate on the revised version, use `question` and `mask` from `tasks.jsonl`. To compare a model before and after revision, align the two versions of a sample with `review_log.jsonl`.

## Relation to the original set

Of the 1,013 original image–instruction pairs, **616** are kept (60.8%), **381** are edited (37.6%) and **16** are rejected (1.6%), leaving 997. Among the edits, **221 (58%) change the target** the instruction refers to, which indicates that the mismatch is systematic rather than a typo. Both versions share the same images and masks and differ only in the instruction text.

The image of `id` 509 is corrupted (0 bytes) and unreadable, and is skipped during evaluation.

Masks are single-channel grayscale. Their pixel values take only 18 distinct levels — 0, a thin compression ring of 1–9, and 246–255 — so any binarization threshold from 10 to 245 gives exactly the same foreground; we binarize at 128. The 101 PNG masks are strictly binary; the ring exists only in the 912 JPEG ones. Masks are also not all the same size: five resolutions occur, most often 1920×1080 and 1280×720, and masks are compared at each sample's own size.

Image and mask paths must be read from the JSONL files rather than constructed from the sample id, because both directories mix `.jpg` and `.png`.
